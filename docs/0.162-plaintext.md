# Opt-in V2 transport for routed models

Some gateways route an OpenAI model name to another model while the provider is
still named `OpenAI`. The old non-OpenAI-provider check does not select that path.
This adaptation targets the exact `rust-v0.162.0-alpha.17.2` source tag.

## Scope

The compatibility mode removes `message.encrypted` from the final V2 tool schema,
including catalog overrides. It treats new spawn/send/followup messages as text,
and converts plaintext `agent_message` items into ordinary user messages in the
outbound request copy. Sender, recipient and message-type context is retained.
V2 mailbox delivery, queue-only messages, wake behavior, automatic completion
results and concurrency limits remain on the original code path.

Tool argument logs retain upstream plaintext redaction. Conversation history may
contain the readable task because this mode deliberately uses plaintext transport.
The environment switch is process-wide: all models launched by that runtime use
this transport until it is unset. HTTPS and API authentication are unchanged.

Only the direct V2 tool surface is accepted in compatibility mode. Calls through
Code Mode fail before delivery, and nonempty `encrypted_function_args` metadata
is rejected before dispatch. This avoids treating ciphertext as ordinary text
or placing nested tool arguments into logs without the direct-call redaction.

Old encrypted task messages can be replayed with an explicit local recovery map.
The map binds each ciphertext's SHA-256 to task text read back through a compatible
native service. Conversion affects only the outbound request copy; the original
encrypted items and their IDs stay in saved history. Missing entries fail before
the request is sent, without dropping messages or presenting ciphertext as text.
The patch never decrypts locally and does not rewrite hidden reasoning items.

Visible history is already reusable when its agent messages are plaintext. In a
live test, a routed model read the prior main history and correctly reported the
original model/effort, fork repository, completed tool tests and preservation goal.
This does not require discarding the conversation or starting the work again.

## Build and use

```bash
git clone --depth 1 --branch rust-v0.162.0-alpha.17.2 \
  https://github.com/openai/codex.git /path/to/clean-codex
bash scripts/build-0162.sh --source-dir /path/to/clean-codex
CODEX_V2_PLAINTEXT_MESSAGES=1 \
  dist/codex-v2-plaintext-0.162.0-alpha.17.2 exec --skip-git-repo-check \
  'Use a V2 child to return a unique marker, then give it one follow-up.'
```

The desktop app accepts a `CODEX_CLI_PATH` override pointing at the built runtime.
Test the CLI first. Do not overwrite the packaged binary or edit saved histories.
Keep the original launcher available to roll back by unsetting both overrides.

## Recover old task messages

Keep the packaged runtime and source histories available. Use the native model
and service that can read the old task ciphertext, with the existing credentials:

```bash
python3 scripts/recover-v2-tasks.py \
  --rollout /absolute/path/to/old-rollout.jsonl \
  --codex-original /absolute/path/to/original/codex \
  --model gpt-6.1-sol --effort low \
  --output /absolute/private/path/recovered-messages.local.json

CODEX_V2_PLAINTEXT_MESSAGES=1 \
CODEX_V2_RECOVERY_MAP=/absolute/private/path/recovered-messages.local.json \
  /absolute/path/to/patched/codex exec fork OLD_THREAD_ID --ephemeral \
  'Read the prior task history without tools and report its pending goal.'
```

Recovery uses ephemeral native threads, submits only encrypted user task items,
and disables configured MCP/plugin integrations. It requests task text, never
hidden reasoning. Two independent readbacks must match before an automatic map
is accepted. The map and evidence file have mode 0600. Never commit these files.

This is model-mediated recovery, not a cryptographic byte-for-byte export or an
official decryption API. A service that rejects the ciphertext, or a changed
backend/key scope, can still prevent recovery. If readbacks differ, no automatic
map is written. The map is explicitly trusted local input: inspect its text before
using it on tasks that require exact instructions. Recovered tasks are not run by
the recovery tool.

For the five old task messages tested here, two `gpt-6.1-sol` readbacks matched,
including a run containing only those five task items. A `gpt-6-luna` check matched
four tasks exactly and reordered sentences in the first. After replacement in a
test copy, the routed model accurately read both the initial test and final task.
Source history files were preserved throughout. These results establish a viable
recovery path for that history, not a guarantee for every encrypted conversation.

The map format is `{"version":1,"messages":{"<ciphertext-sha256>":"task text"}}`.
The runtime requires an absolute map path and rejects invalid entries, opaque
values and maps larger than 4 MiB. Keep `CODEX_V2_RECOVERY_MAP` set for later turns
that replay the same old items. Worklog snapshots can additionally restore goals,
completed actions and evidence; they cannot invent an unrecorded task payload.

For a routed alias that does not support Code Mode or Responses-Lite, generate a
separate catalog for tests. Every other model remains byte-equivalent as parsed
JSON, and the routed alias still uses V2:

```bash
python3 scripts/make-routed-catalog.py \
  --source /path/to/clean-codex/codex-rs/models-manager/models.json \
  --output /path/to/isolated/routed-models.json --model gpt-5.6-sol
# Add only to the isolated invocation; do not overwrite the user's config.toml.
# -c 'model_catalog_json="/path/to/isolated/routed-models.json"'
```

## Coverage and limits

Unit regressions cover request conversion, attribution, unchanged ordinary input,
schema markers, log redaction and explicit rejection of encrypted content. A
successful build alone does not establish gateway/model compatibility. Real
acceptance must exercise spawn, send_message, followup_task, final return, and a
shell call through the configured provider.

Recovery regressions also cover preserved message IDs and attribution, unchanged
source ciphertext, all-or-nothing conversion, missing entries and redacted errors.
Live CLI acceptance has passed mapped parent/child task delivery, formal shell
read, apply_patch creation, Node/GitHub MCP reads, automatic results, same-child
follow-up and queue-only delivery on the next turn. Desktop relaunch acceptance
is a separate activation step.

Public investigation references:

- [Codex history replay failures](https://github.com/openai/codex/issues/25290)
- [Compatible-backend task recovery report](https://github.com/Wei-Shaw/sub2api/issues/7506)
- [V2 plaintext audit discussion](https://github.com/openai/codex/issues/28058)

Missing Code Mode/freeform tool support is a separate provider compatibility
problem. This patch does not declare unsupported `functions.exec`, make deferred
MCP tools discoverable, or change a model catalog to claim new capabilities.
